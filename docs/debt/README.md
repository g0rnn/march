# 부채 기록

이 디렉터리는 단순한 할 일보다 더 많은 맥락이 필요한 구조적 부채를 기록한다. 현재는 임시 뼈대이며 다음 세 문서를 순차적으로 작성할 예정이다.

## 부채 유형

### 기술부채 — `technical.md`

구현, 아키텍처, 테스트, 의존성, 운영 방식 때문에 변경 비용이나 장애 위험이 커지는 상태를 기록한다.

### 인지부채 — `cognitive.md`

코드와 시스템을 이해하기 어렵게 만드는 암묵지, 불명확한 경계, 과도한 복잡성, 부족한 관측성과 문서화를 기록한다.

### 의도부채 — `intent.md`

제품 목표와 구현의 관계가 불분명하거나, 결정 이유가 사라졌거나, 미결정 상태가 오래 유지되어 잘못된 방향으로 굳어질 위험을 기록한다.

## 기록 형식

각 항목에는 다음 정보를 남긴다.

- 발견일과 현재 상태
- 관찰된 사실
- 생기는 비용이나 위험
- 지금 해결하지 않는 이유
- 해결 또는 재검토 조건
- 관련 코드, 명세, ADR, 백로그 항목

부채 문서는 비난이나 막연한 코드 품질 목록이 아니다. 반복적으로 비용을 발생시키는 구체적인 상태와 그 영향을 기록한다. 실행 가능한 해결 작업이 정해지면 `BACKLOG.md`에 별도 항목을 만든다.
